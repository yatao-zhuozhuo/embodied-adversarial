# 同任务训练与评测：SFT、RL、Baseline 的任务和初态划分

讨论日期：2026-10-10。
状态：**已确定第一阶段实验方向；具体题单、初态划分与接口统一尚待实施和验收。**

本文记录本次讨论与代码/资料核查结果。本文不修改正在进行的训练、评测、历史数据或 checkpoint，也不表示当前分支已满足全部划分要求。

## 1. 第一阶段要回答什么

当前优先回答：**在相同任务类型上，SFT 和 RL 是否提高了成功率，以及能否适应该任务内未用于训练的初始状态。** 暂不把未见任务泛化作为主结论。

例如，同一个“把红方块放到绿方块上”的任务，训练时使用一批方块位置与机器人初态，测试时换成独立的一批位置和初态。目标、机器人、控制器、可见信息与成功判据保持一致。

这种设置是合理的任务内评测。结论应写成“训练任务在独立测试初态上的提升”，不能因此声称模型能够解决其他新任务。任务名称相同不等于评测无效；训练与测试实际状态/轨迹混在一起才会削弱实验。

## 2. 统一题目，但正确隔离初态

| 用途 | 初态集合 | 规则 |
|---|---|---|
| SFT 数据构造与训练 | A：训练初态 | 示范和监督样本来自 A |
| RL 训练 | A 或扩充后的 B：训练初态 | 可以与 SFT 训练初态重叠，也可以增加新训练初态 |
| Base、SFT、SFT+RL 的最终评测 | D：测试初态 | **所有模型共享同一个 D；D 与 A/B 的实际初态分开** |

需要纠正的理解：不是 Base 测 A、SFT 测 B、RL 测 C。不同模型各用一批不同测试初态，会把模型提升与场景难度差异混在一起。

SFT 与 RL 的训练任务可以完全一致，也可以让 RL 使用其中一个明确的子集。第一阶段的主要对比应选择有足够 SFT 数据、且 RL 确实训练过的共同任务；没有覆盖的任务单列，不能混作同一训练收益表。

## 3. “换 seed”不等于已经划分成功

seed 是生成或选择初态的控制手段，不是物理状态本身。

- 不同 seed 可能选中相同的有限初态，或没有改变任务相关的物体/目标。
- 同一 seed 在不同版本、不同构造参数、不同随机数调用顺序下也可能得到不同状态。
- 有些变化发生在环境创建/重新配置时，普通 reset 并不改变物体模型或场景几何。
- 恢复专家示范的精确初态时，决定状态的可能是 demo 索引与保存的状态/XML，而不是表面上的 seed。

因此要记录并核验实际初态：任务定义、环境版本、机器人/控制器、seed、初态/demo 编号、场景/对象信息，以及可用的物理状态指纹。必要时使用保存状态或快照。

去重应针对真实状态和任务相关参数，并使用已验证的数值容差；不能只比较 seed 数字，也不能只靠图片 hash 判定所有物理状态相同或不同。

## 4. 四个 benchmark 的任务数量与初态支持

### LIBERO

原 benchmark 共 130 个任务：Spatial、Object、Goal 各 10，LIBERO-100 再分为 LIBERO-90 与 LIBERO-10。

官方提供 `get_task_init_states(task_id)` 和 `set_init_state(...)`，适合直接按初态编号划分。2026-10-10 本机检查发现五个 suite 分别有 10/10/10/10/90 个 `.pruned_init` 文件；各抽查一题，均包含 50 个初态。该抽查不等于已逐题验证全部文件的数量、唯一性和可执行性。

第一版可在确认每题有 50 个有效独立初态后，按 **20 训练、10 验证、20 测试**划分。训练可在训练初态范围内收集多条轨迹；同一个初态重复运行不增加独立状态数量。

专家示范必须核对真实开始状态，不默认 `demo_index` 与 `init_state_id` 一一对应。若要按官方初态重新执行专家动作，必须重新验证动作和成功结果，不能继承原示范成功标签。

来源：[LIBERO 官方仓库](https://github.com/Lifelong-Robot-Learning/LIBERO)。其 90/10 也用于预训练和下游终身学习安排，不能一概解释为永不训练的零样本测试划分。

### MetaWorld

原 benchmark 为 50 个任务；MT/ML 是不同实验设置，不能把 MT50、ML45 等任务数相加当作总任务数。

同一任务可以随机化物体、目标等参数。支持通过环境/任务构造与 reset 的随机机制生成初态；需同时检查创建时 seed、reset seed 和任务参数选择，防止只更换机器人噪声却重复目标配置。

本项目可能排除某些任务，实际可运行集合小于官方 50。最终题单应固定使用的任务 ID、环境版本和控制器，并验证不同初态确实有效且相同初态可以复现。

来源：[MetaWorld 官方使用说明](https://github.com/Farama-Foundation/Metaworld/blob/main/docs/introduction/basic_usage.md)。

### ManiSkill3

ManiSkill3 是持续扩展的任务框架，没有像 MetaWorld 那样固定的单一 50 题列表。

2026-10-10 对本机 `/opt/openeta-swift` 安装的 `mani_skill 3.0.1` 做注册表检查，得到 **74 个环境 ID、66 个实现类**。其中包含不同机器人/难度变体、运动控制和空环境；这两个数字都不能直接称为本项目的有效操作任务数。后续版本和外部任务插件也会改变数量。

多数操作任务通过 `reset(seed=...)` 随机化位置、朝向和目标；物体几何、对象模型等变化可能仅在 `reconfigure` 时发生。例如 PickSingleYCB 更换对象模型与普通位置重置是两个不同层面的变化。

暂不研究新对象/机器人泛化时，可以固定对象范围、机器人和控制器，只划分位置等任务内初态。每个任务仍需确认其 `_initialize_episode` 实际随机化了什么；不是全部 74 个 ID 都适合随机初态评测。

来源：[ManiSkill 任务卡](https://maniskill.readthedocs.io/en/latest/tasks/table_top_gripper/index.html)、[reset 与 reconfiguration API](https://maniskill.readthedocs.io/en/latest/api/mani_skill/index.html)。

### RoboCasa / RoboCasa365

原 RoboCasa 为 100 个任务：25 个原子任务和 75 个组合任务。当前项目接入的 RoboCasa365 为 **365 个任务：65 原子、300 组合**。不能混用两个版本的数量，也不能把同一任务的 `pretrain`/`target` 注册 ID 算成两种任务。

官方环境支持 seed、厨房布局/风格、对象划分等配置。第一阶段可以固定场景和对象范围，在相同任务中改变物体摆放、机器人初态等；从 `pretrain` 切到 `target` 还涉及场景/对象分布变化，比单纯更换初态更强，不必作为当前主实验要求。

本地 `RoboCasaDirectEnv` 已将 seed 传给构造器，并在 reset 时重设环境 RNG；但场景版本、宏配置、重新创建方式和随机调用顺序仍需固定。要按实际场景参数/物理状态去重，不能只比较 seed。

来源：[原 RoboCasa 论文](https://robocasa.ai/assets/robocasa_rss24.pdf)、[RoboCasa365 官方站点](https://robocasa.ai/)、[官方环境参数](https://github.com/robocasa/robocasa/blob/main/robocasa/environments/kitchen/kitchen.py)、[官方评测说明](https://robocasa.ai/docs/build/html/benchmarking/benchmarking_overview.html)。

## 5. 当前项目的实际覆盖与重合

统计口径：SFT 使用 `SFT-train/mixed-data/train.jsonl` 的实际样本；RL 使用基础清单和课程配置中的任务池；v2 使用冻结 `manifests/all.json`。RL 任务池不代表每个 checkpoint 已完成全部任务训练，具体要看其 rollout/更新记录。

| Benchmark | SFT 实际任务 | RL 基础任务池 | RL 含课程任务池 | baseline v2 测试任务 |
|---|---:|---:|---:|---:|
| LIBERO | 8 | 5 | 5 | 20 |
| MetaWorld | 6 | 5 | 11 | 20 |
| ManiSkill | 3 | 17 | 17 | 11 |
| RoboCasa | 1 | 5 | 5 | 18 |
| 总计 | 18 | 32 | 38 | 69 |

SFT 是 74 条 episode、3521 个决策样本；v2 每题 3 个初态，共 207 次计划评测/模型。这些不是同一个数量单位。

按任务类型计算：

- SFT 与 RL 基础 32 题重合 13 题；与 RL 含课程 38 题重合 14 题。
- SFT 与 v2 重合 0 题。
- RL 基础与 v2 重合 2 题：PickSingleYCB、CloseBlenderLid。
- RL 含课程与 v2 重合 7 题：上述 2 题，以及 MetaWorld 的 button-press、button-press-topdown、drawer-close、handle-press、push。

CloseBlenderLid 在 RL 为 RoboCasa `pretrain`，在 v2 为 `target`，属于同一种任务的不同场景划分。此前仅比较完整 env ID 得到的 1/6 题，应与按任务类型得到的 2/7 题区分。

任务定义完全相同、任务家族相似、基本技能共享是三个层次。本次清单归并 RoboCasa 的场景 split；没有声称完成所有任务别名和语义近重复的全面审计。

完整任务对应表：[current-task-membership-20261010.csv](generated/current-task-membership-20261010.csv)。

目前 v2 更适合保留为历史的未见任务/扩展报告，不能直接充当 SFT→RL 的同任务训练收益评测。需要增加共同训练任务的独立初态测试，而不是删除或改写旧成绩。

## 6. 代码核查发现的差异

截至本次检查，不能宣称三个分支已经可靠实现同一初态协议：

| 链路/checkout | LIBERO | MetaWorld |
|---|---|---|
| 主目录 `feat/SFT-train` | `sim/env_registry.py` 的直接包装 `reset(seed=...)` 当前未调用底层 `seed()` | 直接环境创建未像其他两分支一样显式传创建 seed |
| `.worktrees/baseline` | reset 中已调用底层 `seed(int(seed))` | 创建时显式传 seed |
| `.worktrees/rl` | reset 中已调用底层 `seed(int(seed))` | 创建时显式传 seed |

主目录的 LIBERO 仍可能随机生成状态，但不能据清单中的 seed 保证复现或划分。专家精确重放另有 `reference_demo_index` 路径，不能与普通 reset 混为一谈。

ManiSkill 已有 native `reset(seed=...)` 路径；RoboCasa 已有场景 seed/RNG 路径。这些静态代码事实仍不等于逐题真实运行验收完成。

待实施时应统一构造/重置参数和初态记录格式，优先显式支持 LIBERO 官方初态选择；将验证后的行为接入 SFT 构造、RL、baseline 评测三个链路。修复需版本化，新结果与旧运行区分。

## 7. 第一版实验的建议落地方式

1. 从有足够示范、成功判据可靠、初态可变化的任务中选共同题单。可先每 benchmark 5 题，共 20 题；不要求一开始训练全部官方任务。
2. 每题建立训练、验证、测试三份真实初态清单。LIBERO 可先试 20/10/20；其他环境按预算生成 seed 候选，核对物理状态后接受，不能只分三段整数。
3. SFT 构造只在训练初态范围内产生数据，记录专家/模型来源和原始状态。RL 在训练范围内交互，允许扩充训练初态，但不得碰测试状态。
4. 验证集用于 checkpoint/预算/提示词选择。确定模型和设置后，在冻结测试集上一次性生成最终报告。
5. Base、SFT、SFT+RL 使用相同任务、测试状态、机器人、控制器、图像和历史输入规则。所有模型使用相同声明的交互/控制预算；生成配置差异需固定并披露。
6. 第一版可每题测试 20 个独立初态。每个初态一次连续 episode；失败不重置再挑最好结果。若重复采样相同初态，单列模型随机性实验，不算新增独立初态。
7. 用官方成功判据统计，工具执行成功/模型声称完成不算任务成功。基础设施错误单独处理，修复后按同一初态重跑，不能作为额外成功机会或悄悄删掉困难失败。

不同任务可保留不同原生 horizon，但同一任务的不同模型必须使用同一规则。资源不足时，优先减少题数或预先统一测试初态数量，不在看到结果后调整。

## 8. 验收与报告

初态机制至少检查：

- 相同配置/初态在新建环境中可以复现；必要时验证跨设备容差。
- 不同候选初态确实改变任务相关配置，且初始时未成功、场景有效、目标可观察。
- SFT 真实示范、RL 真实训练状态、验证状态和测试状态的对应关系已审计。
- 所有模型实际收到的同任务观测和动作契约一致。

测试报告建议每题记录：真实训练覆盖、测试状态数、成功数/成功率、错误与终止原因。先对任务平均，再对 benchmark 汇总，四个 benchmark 的平均单列；不要按决策样本数给长轨迹更多权重。小样本成绩应保留成功次数并给出适当置信区间。

## 9. RobotWorld 与 CaP-X 带来的参考

[RobotWorld](https://arxiv.org/html/2610.10409v1) 对 84 个任务、5 个通用模型各保留一次 episode，强调任务覆盖、接口预算和执行证据；它没有给出本项目可直接照搬的 SFT/RL 数据划分。

[CaP-X](https://arxiv.org/html/2603.22435v1) 核心评测为 7 个任务，每任务/接口层级 100 次；CaP-RL 在 Lift/Stack/Wipe 三个任务训练并评测提升，还测试感知变化与实机迁移。CaP-RL 的训练使用特权 S1 接口，不能直接当作本项目 RGB＋原生动作设置的同等证据。

两者说明“覆盖更多任务”和“同任务充分重复、比较训练收益”是不同实验目标。当前优先采用后者，并沿用清晰预算、独立成功检查和完整执行审计；未来另行开展任务泛化，不把两类成绩混为一个含义不明的总分。
